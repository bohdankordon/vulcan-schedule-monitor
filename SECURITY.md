# Security Policy

## Supported versions

Vulcan Schedule Monitor is in early development and has no production release. Security fixes are applied to the latest code on the `main` branch only.

## Reporting a vulnerability

Please use GitHub's private vulnerability reporting feature from the repository's **Security** tab when available. This keeps the report confidential while it is assessed.

If private reporting is unavailable, open a public issue containing only a minimal, non-sensitive description and ask the maintainer for a private communication channel. Do not publish exploit details or sensitive evidence.

Never attach credentials, passwords, usernames, cookies, session IDs, authentication state, HAR captures, request-verification tokens, real school identifiers, employee or student information, or other personal school data to a public GitHub issue. Revoke exposed credentials and session material immediately.

Security reports should describe the affected revision, expected impact, and safe reproduction steps using synthetic data where possible.
