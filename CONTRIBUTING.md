# Contributing

Thank you for helping improve Vulcan Schedule Monitor.

## Development setup

Install a Java 21 JDK. Use the included Maven Wrapper so local and CI builds use the same Maven version; a system Maven installation is not required.

Run the complete test and quality suite:

```shell
./mvnw -B -ntp verify
```

On Windows, use `.\mvnw.cmd -B -ntp verify`.

Apply Java formatting with:

```shell
./mvnw spotless:apply
```

On Windows, use `.\mvnw.cmd spotless:apply`.

## Workflow

Create a short-lived branch from `main`. Use a descriptive prefix such as `feat/...`, `fix/...`, `chore/...`, or `docs/...`. Keep changes focused and use [Conventional Commits](https://www.conventionalcommits.org/) for commit messages.

Open pull requests against `main`, explain the change and its verification, and keep documentation aligned with behavior. Pull requests are squash-merged after review; do not squash the branch history merely to prepare it for review.

## Security and privacy

Never commit secrets or sensitive research data. In particular, do not add HAR files, passwords, usernames, cookies, session IDs, request-verification tokens, application GUIDs, bot tokens, real school identifiers, employee names, student data, or raw production responses. Keep authentication/session-state files outside Git, even when generated by future browser automation.

Use synthetic, anonymized examples in tests and documentation. Follow [SECURITY.md](SECURITY.md) when reporting a vulnerability.
